    Three steps to your first call.

    An administrator approves your account. You choose what the token can reach. Your client does the rest.

    1. Request access

      Submit a username and password. You can sign in once an administrator approves the request. No invitation code is needed.

    2. Choose the token scope

      Create an MCP Access Token for selected projects and servers, or for product Knowledge and General Memory only. The secret is shown once.

    3. Connect your client

      Add the endpoint and token to Codex or another MCP client. Delete the token in the console and its next request is refused.

    [mcp_servers.relay_mcp]
url = "http://<relay-host>:3001/mcp"
bearer_token_env_var = "RELAY_MCP_TOKEN"
default_tools_approval_mode = "prompt"

    Codex reads the token from an environment variable, so the secret stays out of the config file.

    Questions before you connect

    Which credentials does Relay manage?

    MCP Access Tokens connect clients such as Codex to Relay. Relay Agent Tokens connect configured Windows agents. Neither is a model provider API key, and neither can stand in for the other.

    Do I need a project to use Knowledge?

    No. Product Knowledge and General Memory follow a permission on your account. Project Memory requires access to its project.

    When does an experience become Memory?

    An agent submits a candidate with memory_capture. It becomes searchable only after an administrator confirms it.

    Does Relay need an inbound port on Windows servers?

    No. The Relay Agent runs as a Windows service and only makes outbound requests to Relay to collect jobs and return results.
