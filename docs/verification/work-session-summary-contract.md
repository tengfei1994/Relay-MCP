# Work Session scope and summary contract

This documents the corrective implementation for #44/#45. It is a local regression result, not a claim that the pending nonproduction operational recheck passed. The earlier operational reports remain historical evidence.

Every HTTP and MCP Session read, list, update, close, event list, and summary checks the owner and Knowledge read ACL plus current control-plane access. HTTP checks current project ownership. MCP resolves current token project scopes, including revocation since the connection was registered. An existing Knowledge ACL and administrator role do not substitute for that scope. Session-associated Candidate compile and job-read endpoints apply the same gate. Lists omit inaccessible sessions without changing their ACL rows.

`GET /api/knowledge/sessions/:id/summary?limit=50&offset=0` and `knowledge_work_session_list({sessionId,limit,offset})` return:

- The original owner-authorized `session`, including IntentEnvelope, final summary, unknowns and acceptance results. This preserves the existing close/reconnect contract. These fields are not copied into outer tool telemetry.
- `events`, preserving `id`, `event_id`, `event_type`, `intent_step`, `objective_ref`, `acceptance_criterion_ref`, and `created_at`; time ties retain insertion order. `eventCounts` counts all authorized correlated events, not just the page.
- `observations`: ID, event ID and creation time, joined through a domain event whose actor, project, environment and Session reference match.
- `evidence`: ID, immutable SHA-256, byte count and creation time, joined through a matching Observation or Candidate. Deleted Evidence, unmatched environments and Evidence without access from the Session project are omitted. Content, storage paths and source locators are not returned.
- `retrievals`: durable receipt ID, creation time, degradation flag, result count and operation (`search` or `document_read`). Older receipts without an operation are read as `search`. The receipt must match Session, actor, project and environment. Query text, result text and result metadata bodies are not returned.
- `pagination` for each category: total, returned, limit, offset and hasMore. The same offset/limit is applied independently to each category; default 50, maximum 200, offset maximum 1,000,000. Reads use one database snapshot. The events HTTP endpoint and MCP get response also expose their events pagination; the complete summary supports subsequent pages.

Legal standalone references created through `correlateEvent` retain their existing Session-authorized visibility. They cannot authorize an Observation or Evidence join: those require a verified backing domain event. A present domain/retrieval record with conflicting scope is excluded, even if its correlation row points at this Session. Legacy records missing sufficient authoritative scope are not promoted into joined results. This distinction is reported in `coverage`.

New Session-aware standard HTTP/MCP Knowledge searches, Product Context Pack Relay sections, Product engine searches and diagnosis retrievals record metadata-only receipts in the existing retrieval-run and Session-event tables. Receipts contain the query SHA-256 and a source-run ID digest, not raw query or results. Replaying the same source run is idempotent; separate retrieval attempts remain distinct. Empty engine sentinel IDs receive a fresh receipt identity. No additional model call or new scope table is introduced. Calls without a Session keep their existing behavior. Historical diagnostic responses or retrieval runs without persisted Session links are not inferred or backfilled; the summary explicitly reports this coverage limit.

Focused regressions cover owner/ACL enforcement, token revocation and project transfer across operations, no list leakage, Candidate job reads, strict joined-source filtering, deleted Evidence, malformed retrieval metadata, same-source receipt deduplication, independent pagination, real registered HTTP/MCP search correlation, full Session response compatibility, legacy event fields and Capture replay. Synthetic private markers are absent from joined Observation/Evidence/retrieval payloads. Deployment acceptance must still exercise this view on the actual closed operational Session and scan only the new telemetry window.


## Optional document read and impact-analysis correlation (#45)

`knowledge_get` accepts optional `workSessionId` alongside its existing `documentId` and optional `project`. The 121-tool catalog and existing required fields are unchanged. Without a Session the response contract remains unchanged. With one, the caller must own an open Session, retain Knowledge read ACL and current MCP token access to its project, and match its environment. An explicitly selected project must resolve to that same project. A missing cold ACL is mirrored only after current control-plane authorization; an existing denial or reviewer grant is preserved.

A successful read writes a `knowledge.retrieval` receipt with `operation: "document_read"`, result count one and no query. The existing query column contains the SHA-256 of the empty string, never document text. Its source identity hashes the canonical document ID, source hash, version/parser metadata and returned body hash. Re-reading the same version in the same Session is idempotent; a different normalized body produces another receipt even when the raw source hash is unchanged. The service checks current scope and active Session state again after asynchronous Product reading and before persistence. A failed read, revoked scope or intervening Session close yields no success receipt. The response remains the original document DTO; the receipt is visible in Session summary, and does not claim a model query or create a model call.

`samplemanager_impact_analysis` continues to accept its existing optional Session/correlation fields and retains its existing result/provenance DTO. After successful relation analysis it rechecks the current selected project/environment/token target and Session access, then atomically writes a standalone `samplemanager.impact_analysis` reference through `correlateEvent`. The receipt identity hashes the Session scope, request options, actual source-backed graph and correlation references, so replay of the same report and references does not add an event. It stores only the event type, hash identity, timestamp, known action/phase value, and digests of free-form phase/objective/acceptance references. Object text, relation bodies, source paths, queries, credentials and hidden reasoning are not copied into the event. The authorized caller still receives the existing source-backed analysis response.

An impact receipt is deliberately not a `relay_domain_events` record. Its Session association cannot authorize joined Observations or Evidence. Even an Observation row that names the standalone receipt is excluded from the summary's authoritative domain-event joins. Existing owner/project/environment/Evidence ACL rules remain the source of access.

Local registered-MCP regressions cover optional schema and 121-tool snapshot compatibility, no-Session response compatibility, document-version replay, changed normalized body under the same raw hash, explicit project-name resolution, cold ACL mirroring, preserved denial/reviewer grants, forged/foreign/closed/unscoped Sessions, wrong project/environment, current token revocation, token revocation or Session closure during Product reading, impact's post-analysis authorization, safe event fields, no inferred Observation join and persistence across store reopening. The first eight scenarios failed before implementation. The final related scope/summary/source-read/relations/remote-scope/catalog run passed 101/101 tests. Strict checking of the new test plus server declarations, project `tsc --noEmit`, and the MCP boundary check also passed (121 registered tools). No active database, service configuration or model was used. The pending deployed operational Session still requires the new get/impact calls and summary verification after upgrade.


### Outer MCP telemetry for document reads and impact analysis

The MCP HTTP entry point writes `tool_called` before tool schema/handler validation. These two operations therefore have a dedicated audit allowlist independent of their safe Session receipts. Document IDs, project/environment selectors, object/relation identifiers and free-form correlation references are represented by SHA-256, character count and UTF-8 byte count. Only canonical Session IDs, bounded integer options, the closed direction enum and the boolean verified-only option remain raw metadata. Unknown fields (including hidden reasoning or query/body-shaped values) are omitted even when execution later rejects the request. The handler and schema validator receive their original arguments; authorized source responses and no-Session output contracts are unchanged.

Independent review identified this pre-handler gap after the initial receipt tests. Both a projection regression and a real MCP HTTP regression were observed failing before the audit fix and passing afterward. The HTTP regression runs `src/mcp/index.ts` against fresh temporary app/Knowledge databases and covers successful, unknown-parameter, and rejected-Session calls for both tools. It checks actual `audit.jsonl`, captured process logs, Knowledge audit rows, Session-event rows and retrieval receipts for synthetic private markers, while confirming the original authorized document/impact response values and zero provider admissions. The final audit compatibility group passed 14/14, receipt/catalog compatibility passed 21/21, and strict TypeScript passed. These local checks do not replace the post-deployment incremental scan or rewrite historical logs.


The generic sanitizer also now recursively redacts an explicit, case-insensitive set of private-reasoning keys: hidden reasoning, reasoning / reasoning content, chain of thought, thought(s), thinking, CoT, scratchpad, reflection, internal monologue and deliberation, including the supported camel/underscore/hyphen/space spellings. Values become redaction metadata, including at nested array/object depths. Ordinary unknown business fields and user-visible `reasoningSummary` remain unchanged; this is not a blanket unknown-argument removal policy. A new nested/array regression and an additional real `relay_mcp_info` outer-audit call first reproduced the leak, then passed after the generic defense. The actual generic tool audit retained its ordinary business selector while redacting nested reasoning. Final audit/event compatibility passed **27/27**, with strict TypeScript and diff checks passing. The dedicated get/impact projections and business handlers are unchanged from the preceding correction.
